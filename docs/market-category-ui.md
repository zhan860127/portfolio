# 50 件商品怎麼分類 — 規劃與實作狀態

> **狀態（2026-11）**：五個階段都做完了。
>
> | 階段 | 內容 | 狀態 |
> |---|---|---|
> | 1 | `market_categories` 表 + `market_products.category_id`（migration 0003） | ✅ |
> | 2 | 後台分類管理頁（新增／改名／刪除／排序） | ✅ |
> | 3 | 商品編輯的分類下拉 + 批次指定分類 | ✅ |
> | 4 | 前台分類膠囊列 + 網址同步（`?c=senya`） | ✅ |
> | 5 | 快照列表由單列改成網格 | ✅ |
>
> 實際的用法是「森野」底下有森野 01、森野 02 —— 同一個系列、
> 各自獨立的作品，各有自己的編號、價格與狀態。
>
> 尚未處理：**Vercel 上的 Neon 還沒跑 migration 0003**。

市集現在是為「十幾件」設計的。商品數量一旦來到 50 件，
瀏覽方式會先壞掉，分類才有意義 —— 所以這份規劃從「現在會卡在哪」開始。

---

## 1. 現在 50 件會卡在哪

| 元件 | 現在的設計 | 50 件時 |
|---|---|---|
| 全螢幕瀏覽器 | 一次一件，左右切換 | 要看到最後一件得點 **49 次** |
| 商品快照列表（`MarketSnapshotSheet`） | **單列**水平捲動，縮圖 112px + 間距 12px | 總寬 6,200px，375px 的手機上一次看 3 件，**要滑 17 個螢幕** |
| 首頁入口 | 顯示「本次共 N 件作品」 | 文案成立，但點進去就是上面那兩個問題 |

**結論：分類不是「加個篩選器」，是把快照列表從單列改成網格，再用分類把網格切短。**
只加 chip 不改列表，客人還是得在一條 6,200px 的帶子上找東西。

---

## 2. 設計原則（對應「簡潔、易懂」）

1. **一件作品只屬於一個分類。** 不做多標籤。
   （一個分類底下會有很多件作品，但每一件作品都是獨立的商品項目 —— 市集是「一單一件」，
   分類只是瀏覽用的歸類，不是把同款作品合併成一個品項。）
   多標籤看起來彈性，實際後果是：各分類件數加起來不等於總數、客人看完「杯」
   再看「茶器」又看到同一個杯子、你自己在後台也會忘記某件到底掛了幾個標籤。
   一件一類，數字才對得起來。
2. **分類數量壓在 5～8 個。** 超過 8 個，chip 列本身就需要水平捲動找分類，
   等於把問題往上搬一層。每一類少於 3 件就併進「其他」。
3. **永遠看得到件數。** 「杯 (12)」比「杯」有用太多 —— 客人才知道點進去值不值得，
   也才看得出來這場主打什麼。
4. **只有一層。** 不做「茶器 → 茶杯 → 聞香杯」這種樹狀。手機上多一層就是多一次迷路。
5. **選中的狀態要能分享、能返回。** 分類寫進網址，按上一頁要回到前一個分類。

---

## 3. 前台：怎麼操作

### 3.1 分類膠囊（chip）列

放在商品列表（快照列表）的最上方，固定不跟著捲動：

```
┌──────────────────────────────────────────┐
│  ●全部 50   杯 12   碗 8   盤 6   瓶罐 9  …→│   ← sticky，可水平捲動
├──────────────────────────────────────────┤
│  ▦   ▦   ▦                               │
│  ▦   ▦   ▦     ← 每列 3 件的網格           │
│  ▦   ▦   ▦        （取代現在的單列）        │
└──────────────────────────────────────────┘
```

- 第一顆永遠是「全部」，而且預設選它 —— 客人不需要先做選擇才能開始看。
- 選中的那顆用品牌色實心底，其餘是細框 + 中性色。只靠顏色不夠，
  選中的要同時帶 `aria-selected`，螢幕閱讀器才知道。
- 點目前這顆 = 回到「全部」（跟列表「點目前這件就是關閉」的既有手勢一致）。
- chip 列本身可以水平捲動，但**分類控制在 8 個以內就不太需要滑**。

### 3.2 網格

實作出來是每列 3 格（sm 以上 4 格），最高佔畫面 46%，
上方仍然看得到目前瀏覽的那一件（需求 5.3）。

- 每列 3 件（375px 手機上每格約 108px，跟現在的縮圖差不多大）。
- 一樣保留「已瀏覽」的淡化、「目前這件」的品牌色外框。
- 高度仍然只佔畫面下半部，上方留可見區 —— 需求 5.3 要求「不能遮蔽所有操作、
  不能讓使用者失去目前瀏覽位置」，這條不能因為改網格就破功。
- 切換分類後，自動捲到該分類的第一件；如果目前瀏覽中的那件就在這個分類裡，
  改成捲到它身上。

### 3.3 網址

```
/market/{marketId}?c=cup
```

- 可以把「這場的杯子」直接貼給朋友。
- 瀏覽器上一頁 = 回到上一個分類，而不是直接離開市集。
- 不明的 `c` 值一律當成「全部」，不要報錯。

### 3.4 空狀態

某個分類整類都賣完、或被篩選條件清空時，不要只留一片白：

> 這個分類的作品都被帶走了。
> 〔看看其他分類〕

### 3.5 刻意不做的事

| 不做 | 原因 |
|---|---|
| 下拉選單（`<select>`） | 手機上要點開、要捲、看不到件數，而且看不出總共有哪些分類 |
| 左側篩選欄 | 手機沒有左側 |
| 多選複選框 | 「杯 + 碗」的交集幾乎沒人需要，但每個客人都要多想一次 |
| 搜尋框 | 50 件還不需要打字；真的要搜，是 150 件以上再說 |
| 排序選單（價格、時間、熱門） | 控制項一多就不簡潔。真的要，只加一個「只看可購買」開關就夠 |

## 4. 後台：怎麼指定分類

### 4.1 單筆

商品編輯頁加一個下拉，就在「作品名稱」下面。選項是固定清單，不給自由輸入 ——
自由輸入的下場是「杯」「杯子」「茶杯」變成三個分類。

### 4.2 批次（50 件的關鍵）

50 件逐一點進去改是 50 次往返，這才是真正的痛點。商品列表頁要有：

```
☑ 全選    已選 7 件   〔指定分類 ▾〕
☑ 手捏茶杯 ……………… 杯
☑ 聞香杯   ……………… 未分類
☐ 盤築花器 ……………… 花器
```

勾選多筆 → 一次指定分類。沒有這個，分類功能在你手上就是「50 次」，
很可能你改了 10 件就放棄了，然後前台出現一個半滿的篩選器。

### 4.3 未分類要看得見

後台列表預設把「未分類」排在最前面，數字歸零才算整理完。
前台則把未分類的作品歸進「其他」，不要讓它們消失。

## 5. 資料怎麼存

```sql
CREATE TABLE market_categories (
  id uuid PRIMARY KEY, name text NOT NULL, slug text NOT NULL,
  description text, sort_order integer NOT NULL DEFAULT 0, ...
);
CREATE UNIQUE INDEX market_categories_name_idx ON market_categories (name);
CREATE UNIQUE INDEX market_categories_slug_idx ON market_categories (slug);

ALTER TABLE market_products ADD COLUMN category_id uuid
  REFERENCES market_categories(id) ON DELETE SET NULL;
```

`ON DELETE SET NULL` 是刻意的：刪掉分類時底下的作品只會回到未分類，
不會跟著消失。後台刪除前會先告訴你這會影響幾件。

- **做成一張表，不是程式裡的固定清單。**（原本規劃寫的是共用常數清單，
  實作時改掉了 —— 清嶼要能自己新增「森野」，不該每次都要改程式重新部署。）
  重點不變：商品是從既有清單裡挑，不是每件各自自由輸入，
  所以「杯」「杯子」「茶杯」不會變成三個分類。
- **名稱與代稱都有唯一索引。** 這是分類長歪的主要原因：
  沒擋的話「森野」「森野 」會變成兩個分類，件數再也加不起來。
- **可以是 NULL。** NULL = 未分類，前台顯示成「其他」。
  不要給一個 `'other'` 預設值 —— 那會讓「我還沒分」跟「我決定它是其他」分不出來。
- 純新增欄位，既有資料與既有查詢完全不受影響。

### 分類怎麼取名

分類現在完全由你在後台自訂，可以是系列名（森野），也可以是用途（杯、碗、盤皿）。
兩種混用也不會壞，只是客人看到的那排膠囊會比較難預期。

一個小建議：技法（手捏、盤築、柴燒釉）已經在規格欄位裡，不要再變成分類，
否則同一件作品會讓人覺得「應該出現在兩個地方」。

**新增作品時的流水號**：選了分類而名稱還空著的話，後台會幫你填下一個號碼
（森野 01、森野 02 之後給森野 03）。跨活動統計，所以上一場做到 02、
這一場會接著 03，而不是從頭來。只是預填值，可以直接改掉。

## 6. 要驗的事

| 項目 | 怎麼驗 |
|---|---|
| 件數加總 | 各分類件數相加 = 總件數（一件一類才驗得過） |
| 網址 | `?c=cup` 直接進入就是選中狀態；按上一頁回到前一個分類 |
| 不明分類 | `?c=不存在` 顯示全部，不報錯 |
| 切換後的位置 | 切到某分類後，列表捲到該分類第一件；原本在看的那件若在同一分類則停在它身上 |
| 空分類 | 整類售完時顯示空狀態與「看看其他分類」 |
| 批次指定 | 勾 7 件指定「杯」，7 件全部更新，未勾的不受影響 |
| 既有行為 | 沒有分類的舊活動照常運作（全部顯示、沒有 chip 列也不壞） |

`resolveGestureIntent`。快照列表是 `Teleport` 到 body 的，不是 viewer 手勢層的
子節點，它自己的捲動（`touch-action: pan-y`）根本不會冒泡過去。

唯一的行為差異：在網格內往下滑現在是捲動網格，不會關閉列表 ——
關閉仍然靠頂部那條把手，或點列表以外的區域。
